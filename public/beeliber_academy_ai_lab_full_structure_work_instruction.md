# Beeliber Academy AI Lab 전체구조 작업지시서

## 1. 문서 목적
이 문서는 `beeliber-academy.vercel.app`를 단순 강의 목록형 웹이 아니라,
**교수 가이드가 붙은 실제 AI 실습형 교육 웹**으로 개편하기 위한 전체 구조 작업지시서다.

핵심 목표는 아래 4가지다.

1. 초보자도 처음 들어왔을 때 겁먹지 않게 한다.
2. 교수의 가이드를 받으면서 직접 프롬프트를 넣고 결과물을 뽑게 한다.
3. 페이지 안에서 설명, 실습, 결과물, 수정이 한 흐름으로 이어지게 한다.
4. 마케팅 / 이미지 투 비디오 / 웹앱 개발 / 자동화의 4개 실전 세션으로 자연스럽게 분기되게 한다.

---

## 2. 서비스 핵심 방향
Beeliber Academy는 “AI를 설명하는 교육 웹”이 아니라,
**AI를 실제로 써보면서 결과물을 만드는 실습형 교육 웹**이어야 한다.

즉, 사용자는 아래 경험을 해야 한다.

- 교수의 짧은 설명을 본다.
- 바로 프롬프트를 입력한다.
- 결과물을 확인한다.
- 다시 수정 요청한다.
- 최종본을 저장한다.

이 흐름이 한 화면 안에서 이어져야 한다.

---

## 3. 전체 UX 컨셉
전체 UX는 `Professor Mode AI Lab` 구조로 설계한다.

모든 실습 페이지는 기본적으로 아래 3단 구조를 사용한다.

- **왼쪽:** 교수 가이드 카드
- **가운데:** 실제 AI 입력 화면
- **오른쪽:** 결과물 카드 및 검수 카드

즉, 사용자는 강의 자료를 읽기만 하는 것이 아니라,
한 화면 안에서 **설명 보기 → 입력 → 결과 확인 → 수정 → 저장** 흐름을 경험해야 한다.

## 5. 홈 화면 개편안

### 목적
첫 화면에서 바로 아래 3가지를 이해시켜야 한다.

- 무엇을 배우는가
- 어떻게 배우는가
- 무엇이 남는가

### 블록 구성

#### 5-1. 히어로
**헤드라인**
실습으로 배우고 결과물로 남기는 AI 교육

**서브 카피**
광고 문구, 숏폼 기획, 웹앱 기획, 자동화 설계까지
교수 가이드와 실제 AI 실습 화면으로 바로 익히는 Academy

**CTA**
- AI 처음 시작하기
- 실전 세션 보러가기

#### 5-2. 4개 실전 세션 카드
- 마케팅
- 이미지 투 비디오
- 웹/앱 개발
- 자동화

각 카드에는 아래 요소 포함:
- 한 줄 설명
- 만들 결과물 예시 3개
- 난이도
- 바로 실습 시작 버튼

#### 5-3. 실제 실습 화면 미리보기
AI 채팅 입력창 + 가이드 카드 + 결과 카드가 함께 있는 UI 목업을 홈에 노출한다.
문장보다 화면 예시가 먼저 보여야 한다.

#### 5-4. 결과물 예시 블록
- 광고 문구 세트
- 8컷 숏폼 플랜
- 웹 서비스 기획서
- 자동화 흐름 설계표

#### 5-5. 학습 방식 소개
- 설명만 듣지 않음
- 예시 프롬프트 제공
- 결과물 즉시 출력
- 수정 버튼으로 재시도
- 최종 결과 저장 가능

- 하단 고정 CTA 바 유지

## 9. 실전 세션 설계 방향

### 9-1. 마케팅 세션
목표:
광고 문구, SNS 글, 제목, 설명, 해시태그, 썸네일 문구를 AI로 빠르게 뽑고 고치게 한다.

핵심 결과물:
- 제목 10개
- 설명 3개
- CTA 5개
- 해시태그 15개
- 썸네일 문구

### 9-2. 이미지 투 비디오 세션
목표:
이미지 한 장에서 시작해 숏폼 장면 흐름, 자막, 썸네일까지 뽑게 한다.

핵심 결과물:
- 시작 이미지 프롬프트
- 장면별 영상 프롬프트
- 자막 문구
- 썸네일 문구
- 업로드 패키지

### 9-3. 웹/앱 개발 세션
목표:
서비스 아이디어를 화면 구조, 기능 목록, 사용자 흐름, 작업지시서로 정리하게 한다.

핵심 결과물:
- 서비스 한 줄 소개
- 화면 구조
- 핵심 기능 목록
- 사용자 흐름
- 개발 작업지시서 초안

### 9-4. 자동화 세션
목표:
반복 업무를 입력/처리/결과 구조로 나누고, 자동화 흐름과 역할 분리를 설계하게 한다.

핵심 결과물:
- 반복 업무 정의
- 입력 / 처리 / 결과 구조
- 역할 분리
- 단계별 요청문
- 최종 출력 형식

## 10. 페이지 1~4 설계 원칙
입문 페이지 1~4는 세션 분기 전 사용자 적응 구간이다.

핵심 목표:
- 페이지 1: AI에 한 줄 말 걸어보기
- 페이지 2: 다시 시키는 법 익히기
- 페이지 3: 긴 글을 쉽게 정리하는 경험하기
- 페이지 4: 내 파일을 넣고 질문하는 경험하기

각 페이지는 반드시 아래 흐름을 가진다.

1. 교수 설명 1분
2. 바로 눌러 쓰는 프롬프트 예시
3. 내 주제로 실습
4. 결과 확인
5. 수정 실습
6. 저장 후 다음 페이지 이동

# 12. 페이지 2. AI에게 잘 물어보는 방법

## 16. 결과물 도출 방식
모든 세션과 입문 페이지는 아래 4단 구조로 결과물이 나오게 설계한다.

### Step 1. 입력
사용자가 폼과 프롬프트 칩을 사용해 기본 정보를 입력한다.

### Step 2. 초안 생성
AI가 구조화된 카드 단위 결과물을 생성한다.

### Step 3. 수정
사용자가 액션 칩 또는 추가 프롬프트로 다듬는다.

### Step 4. 최종 저장
최종본을 저장하고 과제 제출 또는 개인 결과물 보관으로 연결한다.

저장 포맷은 최소 아래 3개를 지원하는 것이 좋다.
- 초안
- 수정본
- 최종본

## 17. 정확한 결과물 유도를 위한 시스템 장치

### 17-1. 입력 강제 구조
빈 자유 입력만 두지 않는다.
필수 입력폼을 먼저 채우게 한다.

### 17-2. 출력 형식 강제
AI에게 항상 섹션별로 나눠 출력하게 한다.
예: 제목 / 설명 / CTA / 해시태그

### 17-3. 검수 카드 제공
결과물 옆에 체크리스트를 항상 붙인다.

### 17-4. 재시도 버튼 제공
사용자가 다시 쓰기 어려워하지 않게 빠른 수정 버튼을 둔다.

### 17-5. 최종본 잠금
최종본 저장 시 버전을 분리해 초안이 덮어씌워지지 않게 한다.

## 21. 개발자 전달용 핵심 요구사항 요약
1. 현재 LMS 느낌보다 AI 실습툴 느낌이 먼저 나야 한다.
2. 모든 실습 페이지는 좌측 가이드 / 중앙 입력 / 우측 결과 카드 구조를 기본으로 한다.

5. 결과물은 초안 / 수정본 / 최종본으로 저장 가능해야 한다.
6. 4개 세션은 하나의 공통 UI 프레임 안에서 내용만 바뀌는 구조로 개발한다.
7. 교수처럼 가이드하는 문구를 UI에 자연스럽게 삽입한다.
8. 페이지 1~4는 단순 설명 페이지가 아니라, 사용자가 교수 가이드가 붙은 AI 실습 화면 안에서 직접 입력하고, 결과를 보고, 다시 수정하고, 저장하는 입문형 AI 랩으로 구현해야 한다.

## 22. 한 줄 결론
Beeliber Academy는 “강의 목록 웹”이 아니라,
**교수 가이드가 붙은 실제 AI 실습 랩**처럼 보여야 하며,
사용자는 카드형 가이드와 프롬프트를 따라가면서 각 세션별 결과물을 즉시 도출할 수 있어야 한다.
